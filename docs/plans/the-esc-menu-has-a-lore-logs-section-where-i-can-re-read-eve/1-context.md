## Conventions that constrain this

- **No hand-typed or copied `uid://`.** New `.tscn`/`.gd` files get ext_resource references by path only (no `uid=` attribute) — confirmed legal and already the pattern used by the most recent addition, `global/interactables/scenes/info_log_interactable.tscn` (its `[ext_resource]` line has no `uid=` at all). `.gd.uid` sidecar files are generated by the headless import step, not authored by hand.
- **The `unique_id=` integer some `[node]` lines carry is not a Godot engine field** — `info_log_interactable.tscn`'s nodes have none, and it loads and passes the full suite. New nodes added here won't carry one either; existing nodes being renamed keep whatever they already have.
- **Signal arity / verbosity conventions** from `CLAUDE.md` apply to any new signal.
- **1280x720 viewport**, screen-space UI (not the 640x360 design-unit space that applies to assault waves).
- Every module/weapon-unlock invariant test in this project (`test_module_unlock_sources.gd`, `test_weapon_unlock_sources.gd`) exists because a UI list silently failed to reach content that was otherwise fully built. `LogState.total_count()` being a directory sweep already avoids the equivalent failure mode for lore logs (nothing to "forget to add"), so no new invariant test is needed on that axis — the new tests instead need to prove the *list* actually walks the *whole* catalogue rather than truncating it, which is the one way this feature could repeat that failure shape.
